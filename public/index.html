Decentralised Super Intelligence · open source

Every AI model.
Routed on your device.

Synapse is an open-source router that runs on your machine. For each request it:

  • works out what kind of expertise is needed;
  • removes what identifies you;
  • sends it to the cheapest expert that is good enough: a local model, your own API keys, or the open network.

A slow expert gets a backup, a failed one is replaced mid-answer, and a stronger expert is asked only when the answer looks uncertain.

How it works

A scheduler for intelligence, running where your data lives.

Before any model sees a request, Synapse decides what kind of intelligence it needs, how much, who should supply it, and how much of your context may leave the device. The first three steps typically take under a millisecond and never touch the network.

1

Understand

Classifies the domain on a taxonomy (finance.quant.derivatives → finance → general) and estimates difficulty, freshness and tool needs from the request's structure.

2

Protect

Replaces emails, phone numbers, wallets, accounts, IPs and tagged names with placeholders. It also trims context to what this expert needs. The mapping never leaves the device.

3

Choose

Scores every expert on domain fit, predicted quality, latency, price, reliability, tools, cache affinity and privacy. Anything below the quality floor is out, however cheap.

4

Stream & guard

Streams the answer. It starts a backup if the first token is late, and continues on another expert if one fails mid-answer. Cancelling stops all paid work.

5

Escalate & learn

Asks a stronger or independent expert only when the answer looks uncertain. Every outcome, and your feedback, updates the next decision.

Hosted API

No daemon? Change one base URL.

Your Decentralised.si key replaces the vendor key. Request bodies, response shapes, streaming events and tool calls stay byte-for-byte what your SDK expects.

1 · PASSTHROUGH

The exact model you asked for. Proves compatibility; nothing is substituted.

2 · OBSERVE

Shadow mode records what the router would have chosen, at no extra cost.

3 · RECOMMEND

"This could have cost 72% less." Benchmark mode verifies with real runs.

4 · OPTIMISE

Let the router pick per request on difficulty, capability, cost, latency and privacy.

Routing you can audit

The cheapest expert that is good enough. Never just the cheapest.

Most AI stacks send everything to one large model, or retry the same request somewhere else when it fails. Synapse decides per request where it should go in the first place, and it can tell you exactly why.

A floor, not a gamble

Every task gets a quality floor and target from its difficulty and your mode. An expert predicted below the floor is excluded, however cheap. If nothing qualifies, the answer is marked degraded, never passed off.

Every route explained

Eight normalised components per candidate, plus plain reasons: "exact domain match, quality above target, within budget". POST /v1/route shows the whole decision without running a model.

Backups that race

If the first token is late, a backup starts; whichever answers first wins and the other is cancelled. In our demo the backup began at 303 ms and answered at 394 ms, where the slow expert would have taken 800.

No interruption

If an expert fails before answering, the next one takes over. If it fails mid-answer, another continues from the exact point it stopped, and you see one reply.

Escalates only when unsure

Uncertainty comes from confidence, completeness and domain fit. Above the mode's threshold, a stronger expert is asked, or an independent one from a different model family, within budget and deadline.

Learns on your device

Time to first token, latency, cost, success and your ratings update each expert's statistics per domain in a local SQLite file. No central server is in the loop.

Modes

Say what matters for this request.

A mode sets how quality, speed, cost and privacy are weighed. The quality floor applies in every mode.

ModeQualitySpeedCostPrivacyBehaviour
fast0.300.500.150.05Lowest latency above the floor; tolerates more uncertainty
balanced0.400.300.200.10The default
deep0.650.100.100.15Raises the floor and escalates sooner
cheap0.300.100.550.05Cheapest expert that still clears the floor
maximum0.800.050.050.10Strongest expert, plus an independent second opinion and synthesis

Privacy is separate from mode. public sends text as written; pseudonymised (the default) replaces identifiers; confidential also restricts to local or trusted experts; local_only never uses a remote expert. The hosted API accepts its own policies (passthrough, optimise, cheapest, private, byok_only and more) through the X-Decentralise-Mode header.

Open source

Read it, run it, change it.

Every part is public on GitHub:

  • the provider node and the local memory harness;

Install in one line on macOS, Linux or Windows from the download page, or build it from source. The default config uses simulated experts, so you can watch routing, fallback, hedging and escalation work without a GPU or an API key.

# ask; watch it route, stream and explain
curl -N localhost:7766/v1/ask \
  -H 'Content-Type: application/json' \
  -d '{"prompt": "Explain Black-Scholes implied volatility."}'

# the decision only, no inference
curl localhost:7766/v1/route \
  -H 'Content-Type: application/json' \
  -d '{"prompt": "Write a Rust async TCP server."}'

# tests and benchmark
cargo test
cargo run --release --bin benchmark
