Migrate in one line

Change the base URL. Nothing else.

Your Decentralised.si key replaces the vendor key. Request bodies, response shapes, streaming events and tool calls stay byte-for-byte what your SDK expects.

1 · PASSTHROUGH

The exact model you asked for. Proves compatibility; nothing is substituted.

2 · OBSERVE

Shadow mode records what the router would have chosen, at no extra cost.

3 · RECOMMEND

"This could have cost 72% less." Benchmark mode verifies with real runs.

4 · OPTIMISE

Let the router pick per request on difficulty, capability, cost, latency and privacy.

The router

Capability first. Then cost, speed and privacy.

Most gateways retry the same request somewhere else. Ours decides where it should go in the first place, and never trades away a feature your app depends on.

Never a silent downgrade

If your request uses tools, JSON schema, vision, reasoning or a long context, only models that support all of it are candidates. Vendor-only features pin the request to that vendor.

Honest provenance

Response headers always name the requested and the actual model and provider, with a receipt. A response never claims a model that didn't produce it.

No interruption

If a provider fails mid-stream, the answer continues on another provider from the exact point it stopped. Failover spreads across different vendors, not three copies of the same one.

Blind by design

Routing uses the request's structure and your optional hints, not its meaning. Identity is stripped before a provider sees anything, and each conversation goes to a different provider.

Bring your own keys

Connect Anthropic, OpenAI or Gemini accounts. Keys are envelope-encrypted, and you pay those vendors directly at their prices.

Limits that hold

Requests per minute, tokens per minute, and daily and monthly spend caps per key, per workspace and per organization, enforced at the edge with standard rate-limit headers.

Routing modes

Set a policy once, or per request.

ModeBehaviour
passthroughAlways the provider and model the application requested
optimiseWeighs quality, cost, latency and decentralisation, above a quality target set by the request's difficulty
cheapestLowest expected cost that meets the quality threshold
fastestLowest latency that meets the quality threshold
qualityHighest expected quality within budget
privateOnly providers that meet strict privacy
decentralised_onlyNever centralised commercial providers
byok_onlyOnly providers you've connected your own keys for
network_onlyOnly providers on the open Decentralised.si network

In chat and the playground, choose auto to let the router decide, or pick a model to use exactly that model.
